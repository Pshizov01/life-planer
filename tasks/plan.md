# Implementation Plan: Life Planner

## Overview

Личный трекер пяти жизненных сфер (спорт, привычки, питание+сон, учёба, финансы) на React+Vite+Tailwind+Supabase, задеплоенный на Vercel. Реализация — вертикальными срезами: сначала фундамент (проект, БД, авторизация), затем каждая сфера целиком (схема → хук → страница → график), затем сводный дашборд и деплой.

## Architecture Decisions

- **Одна таблица на сущность, RLS на всех** — проще поддерживать, чем шарить одну JSON-колонку под всё; см. `docs/SPEC.md`.
- **`daily_log` — одна строка на дату** (unique(user_id, date)), питание и сон объединены, т.к. оба логируются раз в день одним действием.
- **Намазы — обычные привычки** в таблице `habits` (5 seed-строк), а не отдельная сущность — не усложняет модель данных.
- **Расчётная логика вынесена в `lib/calculations.js`** и покрыта тестами до реализации (TDD) — стрики, прогресс целей, агрегации для графиков.
- **Порядок сфер:** Привычки → Спорт → Питание/Сон → Учёба → Финансы — от простой схемы (одна таблица) к более сложной (несколько таблиц + агрегации), чтобы паттерны устоялись до самых сложных срезов.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Supabase free-tier проект «засыпает»/удаляется после ~1 недели полной неактивности | Med | Регулярное использование само по себе решает; при первом деплое предупредить пользователя об этом лимите |
| Рассинхронизация дат/таймзон в `daily_log` (один ряд на дату) | Med | Использовать локальную дату устройства (`new Date().toLocaleDateString('en-CA')` → YYYY-MM-DD) единообразно во всех формах |
| Неверная RLS-политика открывает данные всем | High | Явно тестировать: запрос без сессии должен возвращать пусто/ошибку, до того как срез считается готовым |
| Дрейф стилей между страницами (5 разных форм/списков) | Low | Общие компоненты (`Card`, `EntryForm`, `ChartWrapper`, `ProgressBar`) создаются в Task 1 и переиспользуются везде |
